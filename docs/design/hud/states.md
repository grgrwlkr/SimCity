# Состояния элементов HUD

Одна таблица состояний на весь HUD плюс отклонения по элементам. Состояние, которого нет в
таблице, не придумывается на месте — оно добавляется сюда.

## Базовая таблица: любой кликаемый элемент

| Состояние | Что меняется | Значения |
|---|---|---|
| обычное | — | фон прозрачный, текст `--hud-ink`, без кромки |
| наведение | фон | `--hud-hover`, переход `--hud-motion-fast` |
| нажатие | фон + сдвиг | `--hud-press` + `transform: translateY(1px)`, без перехода |
| фокус с клавиатуры | кольцо | `outline: var(--hud-focus-ring)`, `outline-offset: var(--hud-focus-ring-offset)`, `box-shadow: var(--hud-focus-halo)` |
| выбрано / включено | фон + кромка + ARIA | `--hud-accent-fill`, `border: 1px solid var(--hud-accent)`, `aria-pressed="true"` |
| выбрано + нажатие | фон | `--hud-accent-fill-strong` |
| выключено (нет денег, нет места) | текст + курсор | `--hud-ink-disabled`, `cursor: not-allowed`, `aria-disabled="true"`, фон не меняется при наведении |
| закрыто вехой | текст + подпись | `--hud-ink-disabled`, второй строкой caption «Откроется при 250 жителях» |

Правила, которые легко нарушить:

- **Фокус рисуется только на `:focus-visible`.** Клик мышью не обязан оставлять кольцо.
- **Выбор не бывает одним цветом фона.** Заливка даёт к стеклу 1,6–1,9 (`contrast.md`,
  «Заливки состояний») — этого мало, чтобы опознать активный инструмент с одного взгляда. Кромка
  и `aria-pressed` обязательны; кромка — тот же 1 px, что у контура панели, поэтому габарит
  кнопки не скачет между состояниями.
- **`disabled` у кнопки HTML запрещено.** `disabled`-элемент выпадает из Tab-порядка, и игрок с
  клавиатуры не узнаёт, что школа существует и откроется при 250 жителях. Берётся
  `aria-disabled="true"` + игнор клика в обработчике.
- **Ничего не мигает.** Вместо мигания — `--hud-warning` на кромке и цифра (сколько осталось).

## Длинный текст и переполнение

| Место | Поведение |
|---|---|
| деньги в баре | `tabular-nums`, разряды неразрывным пробелом; отрицательные — `-$1 234` `--hud-negative` (`hud_bar.rs:27-45`); бар не резиновый, число до 13 знаков помещается |
| подпись кнопки инструмента | одна строка, `min-width` по токену, длинное слово не переносится — сокращается подпись, не кнопка |
| строка тоста | `white-space: nowrap` (порт `TextLayout::no_wrap()`, `toasts.rs:112`), обрезка `text-overflow: ellipsis`, полный текст в `title` |
| проблема советника | перенос по словам, до 3 строк, дальше `line-clamp: 3` |
| строка займа в бюджете | перенос по словам; суммы в своих колонках не переносятся никогда |
| значение под курсором на карте данных | одна строка, при нехватке места — уменьшения шрифта нет, панель шире не делается: текст обрезается |

## Узкая ширина

Минимум — 1280×800 (окно Electron). До 1100 px ширины ничего не меняется. Ниже:

- бар: группа скорости сжимается до иконок без подписи `×3`, деньги и часы остаются;
- палитра: группы переносятся во вторую строку, разделители остаются между группами;
- бюджет: колонка «Прошлый месяц» скрывается первой, ширина панели падает с 560 до 420;

## Левая колонка

Карты данных и советник стоят в одной левой колонке (`layout.md` §5, §8) и на любой ширине окна
открыты по одной:

- открытие советника сворачивает панель карт данных до заголовка; выбранная карта остаётся на экране,
  её имя — в заголовке;
- разворот панели карт данных закрывает советника;
- по умолчанию панель карт данных свёрнута.

## Клавиатура и геймпад

- Tab-порядок: бар → палитра → открытые панели → тосты. Внутри палитры стрелки ходят по
  кнопкам группы, Tab переходит к следующей группе (паттерн toolbar, `role="toolbar"`).
- Хоткеи инструментов — цифры и `O`, как в Rust (`tool_palette.rs:128-155`); **гейт по фокусу**:
  пока фокус в `input`/`textarea`, хоткеи не срабатывают (порт
  `undo_hotkey_is_ignored_while_keyboard_is_captured`).
- `Esc` закрывает верхнюю открытую панель, потом уводит в меню (уже есть:
  `Hud.tsx:78-88`).
- Экран бюджета — модальный: фокус держится внутри, `Esc` закрывает, возврат фокуса на кнопку
  «Бюджет».
- Геймпада в порту нет и он не проектируется: игра — мышь и клавиатура.

## Обратная связь по времени

Любое действие игрока отвечает **внутри 100 мс**: наведение и нажатие — `--hud-motion-fast`
90 мс; выбор инструмента, включение слоя, смена скорости — без перехода, 0 мс. Команда, которая
уходит в воркер (постройка, заём), красит кнопку нажатой сразу, не дожидаясь снимка.

## Правило клика сквозь HUD

Клик по панели не доходит до карты. В Rust это `PointerOverGameUi` (`hud/pointer.rs`); в вебе —
`pointerdown` на корне HUD с `stopPropagation`, а слой-обёртка, который только центрирует панель,
получает `pointer-events: none` (порт `Pickable::IGNORE`, см. `hud_bar.rs:65`). Подсказка у
клетки — вся `pointer-events: none`: она стоит у курсора и не имеет права съесть тот клик,
который объясняет (`tile_tooltip.rs:69, 84, 102, 110`).
