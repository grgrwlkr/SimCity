# Полный отзыв критика полноты

# Audit Completeness Critique

## Confirmed misses (spot-checked in code)

**1. Keyboard hotkeys have zero egui-focus gating — whole input-edge-case class uncovered.**
The toolbar has a live text field (`ui.text_edit_singleline(&mut p.ui_state.seed_text)`, `crates/simcity_frontend/src/game/ui/toolbar.rs:137`), yet every keyboard consumer reads raw `ButtonInput<KeyCode>` with no `wants_keyboard_input()` check — `rg` finds 0 matches for it repo-wide. Concretely: camera WASD/arrows/Q/E (`crates/simcity_frontend/src/game/camera.rs:53-130`), tool switching Digit1-5 and Ctrl+Z/Y (`crates/simcity_sim/src/game/map/input.rs:57-93`), Space/Escape pause (`crates/simcity_sim/src/game/sim.rs:140-163`). Typing a seed "12345" switches tools 1→5; typing letters pans the camera; space pauses the sim. Notably the mouse IS gated (`egui_wants_pointer_input()` at `map/input.rs:175`), so the asymmetry looks like an oversight, not a decision. frontend-core-debug checked hotkey/README parity but missed this entirely.

**2. No CI whatsoever.**
`.github/workflows/` does not exist. cross-cutting found the symptom (`cargo test` runs 0 tests at root) but never flagged that nothing enforces the documented verification floor (fmt/clippy/test) automatically. Single biggest structural win for next phase: one GitHub Actions workflow (fmt + clippy -D warnings + `cargo test --workspace`) plus `[workspace] default-members` so bare `cargo test` means the workspace.

**3. BRP security / release hygiene — nobody looked.**
`RemotePlugin` + `RemoteHttpPlugin::default()` are added unconditionally in `src/main.rs:20-22` (only wasm excluded) — they ship in `--release`. The custom `bevy_debugger/screenshot` method accepts a caller-supplied `path` (`src/main.rs:160-167`) fed to `save_to_disk` — an unauthenticated arbitrary-path file-write primitive over HTTP for any local process, on top of standard BRP full world mutation. Binding is bevy's default (localhost), so remote risk is low, but no auditor even verified the binding or proposed gating the remote stack (and DebugWorldPlugin's per-frame O(world) scans) behind the existing `dev` feature — which would also structurally fix frontend-core-debug's "18 unconditional snapshot systems" finding.

**4. audio_sfx.rs — an entire subsystem with zero coverage by any auditor.**
96 lines, real issues visible on a skim: SFX availability is gated on CWD-relative `Path::new("assets/sfx/build.ogg").exists()` (`audio_sfx.rs:38-52`) — silently disables audio when launched from any cwd other than repo root, the exact CWD pathology data-persistence flagged for saves but nobody applied here; stale "Bevy 0.17 audio playback" comment; only build/erase of 11 GameCommand variants wired. Camera.rs is similarly unaudited beyond what I checked (pan bounds/zoom clamping unverified).

## Uncovered risk classes (hypotheses, not fully verified)

- **Exit-path behavior**: `auto_dump_on_game_end` (`src/game/mod.rs:22-25`) sets `copy_requested=true` during `OnExit(InGame)`, but the consumer is an egui-pass UI system — whether the flag is actually consumed after the state switch (vs. silently dropped or fired later in MainMenu) is unverified. Also: no save-on-exit or unsaved-changes prompt anywhere — closing the window silently loses the city. No auditor touched exit flows.
- **Long-run soak**: several auditors found unbounded-growth candidates (citizens never despawn, notification/telemetry accumulation) but nobody proposed the systematic answer — a headless `MinimalPlugins` sim harness run for N sim-hours asserting entity/resource counts plateau. That harness is also the enabler for the many "zero test coverage" findings (emergencies dispatch, economy loop, undo/redo roundtrip).
- **Save/load at scale**: all persistence findings are test-city-sized. RON text saves of a full grid with thousands of buildings/citizens — size, save/load latency, and whether load's despawn-then-respawn spike drops frames — unchecked.
- **Determinism across save/load**: load reseeds `StdRng` from the map seed (`persistence.rs:660-663`) but RNG stream position isn't persisted, so pre-save and post-load sims diverge. Probably an accepted trade-off, but it's undocumented and no auditor connected it to the determinism findings from economy-citizens.

## Structural wins for next phase that no auditor proposed

1. CI workflow + `default-members` fix (see #2).
2. Gate BRP remote stack + DebugWorldPlugin behind the `dev` feature (see #3).
3. Shared headless sim-harness test utility — one fixture unblocks ~6 different "zero coverage" findings across auditors instead of fixing them piecemeal.
4. A single `wants_keyboard_input()` guard helper (run-condition) applied to the 4 keyboard-consumer systems fixes the whole class from #1 in one place.
