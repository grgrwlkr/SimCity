# Разворот (U-turn) на тупиковых дорогах — дизайн

**Дата:** 2026-07-08
**Статус:** дизайн одобрен, план реализации в ожидании
**Контекст:** автобус (Phase A общественного транспорта) доезжает до остановки на направленном спуре и застревает — из `dir=North`-плитки нельзя развернуться, а [road_graph.rs:86](../../../crates/simcity_sim/src/game/transport/road_graph.rs#L86) по дизайну разрешает U-turn только на перекрёстках. Нужно разрешить разворот и на физических тупиках.

## Проблема

`build_road_graph` строит направленные рёбра по строгим правилам (straight / lane-change в ту же сторону / повороты только на перекрёстках). U-turn разрешён исключительно на перекрёстках (`dir=None`). Поэтому машина, приехавшая в конец направленного спура (двор, отросток дороги), не может развернуться и выехать — road-A* (`find_road_path_cached`) не находит выезд. Это бьёт по всем, кто ходит через road-A*: **автобусы, сервисные машины, spawn/stuck-fallback обычных машин**.

## Цель

Разрешить разворот на **физических тупиках двухсторонних дорог**: машина, доехавшая до плитки, за которой в её направлении движения дороги НЕТ, может перейти на встречную полосу (перпендикулярно-смежная плитка с противоположным `dir`) и уехать обратно. Реализуется целиком в road-графе; движение и direction-гард не меняются.

## Не-цели

- Разворот в потоке (не на тупике) — запрещён, иначе появится встречка на сквозных дорогах.
- Разворот на one-way дороге одной полосы — физически некуда (встречной полосы нет); корректно оставляем без разворота.
- lanelet-планировщик (основной путь обычных машин) — вне скоупа (обычные машины деспавнятся по прибытии и в развороте на тупике не нуждаются; их stuck-recovery road-A* fallback разворот получит). Унификация роутинга на lanelet — отдельная будущая инициатива.

## Архитектура (только `road_graph.rs`)

### Триггер тупика
Плитка `cur` — тупик для своего направления, если:
1. `cur.dir != RoadDir::None` (обычная направленная плитка, не перекрёсток), И
2. соседняя плитка строго в `cur.dir` (`forward = cur + cur.dir.delta()`) — **не проезжая дорога** (за краем карты, вода, или `road.is_none()`).

Это однозначный физический тупик. НЕ используем признак «нет straight-ребра» — он ложно срабатывает на turn-only полосах перед перекрёстком (у них впереди есть дорога = перекрёсток, это не тупик).

### U-turn-ребро
Если `cur` — тупик и это **двухсторонняя дорога** (`cur.flow != OneWay`), ищем встречную полосу: перпендикулярно-смежную плитку `opp` (для `dir=North/South` — соседи по X; для `East/West` — по Y), где `opp` — дорога, `opp.kind == cur.kind`, `opp.dir == cur.dir.opposite()`. Если найдена — добавляем ребро `cur -> opp` (ставим бит соответствующего перпендикулярного направления в `edges[cur]`).

Геометрия обоснована моделью полос (`roads.rs`): у двухполосной дороги `lane < lanes/2` — прямая полоса (paint dir), `lane >= lanes/2` — встречная (противоположный dir), и лежат они на перпендикулярно-смежных плитках. Значит встречная полоса тупика — перпендикулярный сосед с `dir.opposite()`.

### Почему STRICT-инварианты целы
1. **Direction-гард не трогаем.** `route_is_direction_correct` / `first_oncoming_pair` флагуют шаг только если его направление == `dir.opposite()` плитки. U-turn-манёвр в маршруте = перпендикулярный шаг `cur -> opp` (направление шага перпендикулярно `dir` обеих плиток, значит ≠ `opposite`) + дальнейшее движение по `opp.dir` (совпадает). Оба шага гард проходит — проверено на бумаге, закрепим тестом.
2. **Только на тупиках.** Ребро добавляется лишь когда впереди по `cur.dir` дороги нет → на сквозных дорогах U-turn-рёбер не появляется → встречка в потоке невозможна.
3. **Перекрёстки не затрагиваются.** U-turn только на направленных плитках-тупиках (`dir != None`); правила бокса перекрёстка (`dir == None`) и их inварианты не меняются.

### Движение и рендер
`move_vehicles` едет по тайл-последовательности маршрута; U-turn — обычный перпендикулярный шаг + продолжение по встречной. Поворот спрайта берётся из соседних тайлов (готово). Изменений в movement не требуется.

## Что разблокирует
- road-A* (`find_road_path_cached`) строит «заезд в спур → разворот на конце → выезд».
- Автобус доезжает до остановки-в-спуре и возвращается; демо-маршрут заездит по кругу без залипания.
- Сервисные машины и spawn/stuck-fallback обычных машин выезжают из тупиков разворотом.

## Тесты (пины)
1. **U-turn на two-way тупике** (`transport/tests.rs`): мини-грид с двухполосным спуром, оканчивающимся тупиком. road-A* от входа в спур до тайла на выезде возвращает НЕпустой маршрут, содержащий разворот (перпендикулярный шаг на встречную полосу). Сейчас (до фикса) — пусто.
2. **Негативный: one-way тупик** — на однополосной one-way дороге в тупик U-turn-ребро НЕ добавляется, маршрута наружу нет (разворот физически невозможен).
3. **Негативный: не на тупике** — на сквозной двухсторонней дороге U-turn-ребро НЕ добавляется (у плитки в потоке нет перпендикулярного U-turn-бита).
4. **Инвариант направления** — маршрут с разворотом проходит `route_is_direction_correct` (== true); существующий пин `route_oncoming_ticks_total == 0` на прогоне test city не ослаблять.
5. **Live-смоук** (`--features dev`): автобус объезжает ≥2 остановки (`buses_dwelling` переключается несколько раз за прогон, не залипает на одной), `route_oncoming_ticks_total == 0`.

## Критерии приёмки
1. `build_road_graph` добавляет U-turn-ребро на two-way тупиках по описанному триггеру; на one-way и на сквозных дорогах — не добавляет.
2. `cargo clippy -D warnings` чист (оба feature-конфига), `cargo test --workspace` зелёный, включая новые пины и неослабленный `route_oncoming`-инвариант.
3. Live `--features dev`: автобус реально объезжает круговой демо-маршрут (несколько прибытий на остановки), нарушений направления 0.
