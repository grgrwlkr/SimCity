# Ф2. Деньги как рычаг — план

Цель Ф2 из `2026-09-09-gameplay-goals.md`: B5 целиком плюс честное содержание. Приёмка программы: поднятая ставка налога измеримо снижает спрос своей зоны и класса на прогоне; месячный отчёт сходится с изменением казны до доллара; экран бюджета читается по статьям.

Предусловие закрыто: починка «пауза — не новая игра» (`3cfc3f1` из `worktree-pause-city-reset`) перенесена в ветку cherry-pick'ом.

## Решения

| Развилка | Решение | Почему |
|---|---|---|
| Единица денег | целые доллары, `City.money: i64` | каждая строка отчёта — ровно то целое, что легло в казну, поэтому сверка точна без копеек |
| Путь денег | любое изменение казны проходит через `BudgetLedger::post(item, amount)` | иначе стройка и займы разойдутся с отчётом |
| Класс дохода | стоимость земли под якорем здания: <0.34 низкий, <0.67 средний, иначе высокий | B2 (Ф3) заменит источник класса, ставки и отчёт останутся |
| Месяц | `days_per_month` в `economy.ron`, по умолчанию 10 игровых дней | отчёт должен закрываться за минуты прогона, а не часы |
| Ставки | 3 зоны × 3 класса, 0–20 %, по умолчанию 9 % | нейтральная точка спроса совпадает с умолчанием |
| Спрос | каждый процент выше 9 снижает спрос зоны на 0.04, ниже 9 — поднимает на 0.02; спрос класса считается от ставки своего класса | ставка — рычаг, а не украшение |
| Содержание | дороги — за клетку; сервисы — за здание × финансирование; R/C/I не платят городу | «по зданию, а не по тайлу»; жилые и коммерческие — налогоплательщики |
| Финансирование | 0–150 % по пожарным, полиции, медицине; ниже 100 % радиус охвата сжимается пропорционально, не меньше половины | недофинансирование должно стоить качества |
| Займы | $10 000 / $25 000 / $50 000, 1 % в месяц, 12 месяцев, аннуитет в конце месяца | простая, проверяемая модель |
| Сохранение | ставки, финансирование и займы — аддитивные поля `SaveGameV3` с `serde(default)`; текущий месяц отчёта начинается с загрузки | долг не должен исчезать при загрузке |

## Срезы

| Срез | Что | Тесты |
|---|---|---|
| S1 | `BudgetLedger`: статьи, `post`, закрытие месяца в отчёт; ежедневная экономика и стройка идут через него | `budget_report_*` |
| S2 | содержание по зданию: дороги за клетку, сервисы за станцию, R/C/I ноль | `maintenance_per_building_*` |
| S3 | `TaxRates` и класс здания; налоги по зоне и классу в отчёт | `tax_rate_*` |
| S4 | ставка входит в спрос зоны и класса; `simcity/observe` показывает спрос по классам и ставки | `tax_rate_*` |
| S5 | финансирование сервисов: расход и радиус охвата | `budget_report_*`, `maintenance_per_building_*` |
| S6 | займы: выдача, аннуитет, строки отчёта, поля сохранения | `budget_report_*` |
| S7 | экран бюджета на bevy_ui: статьи месяца и прошлого месяца, ставки, финансирование, займы | `ui_shell_budget_*` |
| S8 | `economy.ron` с новыми полями и parse-тест; снимок `debug_world` | существующие parse- и контракт-тесты |

## Проверка без окна

Верификатор поднимает скрытый экземпляр, открывает бюджет и меняет ставки через `simcity/input {"activate": "hud.budget.…"}`, шагает тики `simcity/sim {"step_ticks": 600}`, читает спрос по классам и отчёт в `simcity/observe`, снимает `simcity/capture {"ui": true}`.

## Риски

- Баланс: снятие содержания R/C/I и новые ставки сдвинут казну демо-города и сценариев. Калибровать на прогоне так, чтобы город на умолчаниях не банкротился и не копил бесконечно.
- Стоимость земли считается чанками; класс здания может меняться между месяцами — это ожидаемое поведение, не шум.
