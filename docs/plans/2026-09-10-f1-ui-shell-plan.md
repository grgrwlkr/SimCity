# План Ф1 — каркас игрового интерфейса на bevy_ui — 2026-09-10

Как сделать фазу Ф1 из `docs/plans/2026-09-09-gameplay-goals.md` (D0–D5, D9, D10, D11; D8 закрыт в Ф0): модули, порядок срезов, тесты и проверка без окна. Приёмка — в документе целей, здесь её не повторяю.

## Опорные факты, проверено 2026-09-10

- Фича `ui`, включённая в `bevy` 0.19 по умолчанию, уже тянет `bevy_ui`, `bevy_ui_render` (`UiMaterial`), `bevy_ui_widgets`, `bevy_input_focus` и `picking`. Новых зависимостей не нужно.
- Виньетка — полноэкранный `bevy_ui`-квад с `GlobalZIndex(-1)` (`crates/simcity_frontend/src/game/vignette.rs`), а не проход рендера, и в том же UI-проходе рисуется до панелей. Мир, просвечивающий сквозь полупрозрачное стекло, поэтому уже затемнён сам: пиксель панели = заливка·g + мир·(1−a)·(1−g). Умножать заливку на `1 − vignette_alpha` значит затемнять сам интерфейс в углах, где стоят тулбар и полоса HUD, — это стилевой выбор, а не исправление. Ручка есть, по умолчанию выключена.
- UI-проход идёт после всех пост-эффектов: тонмаппинг в `Core3dSystems::PostProcess`, bloom в том же наборе перед ним, `ui_pass.after(Core3dSystems::PostProcess)`. Цвета стекла не проходят тонмаппинг, и bloom в них не растекается при любом положении ручки HDR.
- Копии пост-обработанного кадра в конвейере нет. Матовое размытие в Ф1 не делаем: критерий D10 — «полупрозрачные поверх пост-обработанного кадра, а не плоская заливка». Если до размытия дойдёт, проход согласуется с сессией, владеющей камерой и пост-эффектами.
- Офскрин-глаз `simcity/capture` умеет рисовать `bevy_ui`, если корень перенаправить `UiTargetCamera` на глаз до `UiSystems::Prepare`. Масштаб цели-картинки 1.0 против 2.0 у окна на Retina — подгонять под окно и возвращать после съёмки; неактивная камера UI не рисует; размер ограничить потолком 8192. Контракт согласован с сессией observability: маркер `GameUiRoot`, параметр `"ui": true`.
- Кнопка `bevy_ui_widgets::Button` сообщает о нажатии событием `Activate { entity }` — его шлёт и клик, и клавиатура. Программная активация идёт через тот же обработчик.
- Уведомления — ресурс `Notifications` в `simcity_sim`, рисуются egui-системой там же (`notifications.rs`), без группировки: отсюда стена одинаковых тостов.
- Цены и радиусы: `RoadKind::build_cost_per_lane_tile`, `BuildingKind::build_cost`, `BuildingKind::service_radius`; валидность зоны — `can_zone_tile`.

## Решения

1. **Игровой UI — новый модуль `crates/simcity_frontend/src/game/hud/`.** Egui не расширяется ни одним новым экраном.
2. **Egui-панели уходят в `DevUiPlugin`**, который подключается только под новой фичей `dev` у `simcity_frontend`, прокинутой из корневой `dev`. Сам `EguiPlugin` остаётся во всех сборках: на нём стоят гейт фокуса клавиатуры и защита карты от кликов по UI. Egui-тосты в `simcity_sim` заменяются лентой в `hud` и больше не рисуются.
3. **Стекло — `GlassMaterial: UiMaterial`**, WGSL встраивается в бинарь (`embedded_asset!`), без путей от текущего каталога.
4. **Визуальный язык — токены в `hud/theme.rs`**: палитра, шкала отступов с шагом 4 px, радиусы, размеры шрифта 12/14/18/24, цвета состояний hover/pressed/active/disabled. Цветов и размеров вне токенов в `hud` нет.
5. **Взаимодействие без мыши для проверок** — два режима `simcity/input`: `{"activate": "<Name>"}` шлёт `Activate` сущности с этим `Name`, `{"hover_tile": [x, y]}` пишет ресурс-переопределение клетки под курсором. По умолчанию переопределение пустое и поведение игрока не меняет.
6. **Подсказка у курсора ставится у экранной проекции клетки, а не у указателя** — одинаково работает для мыши и для проверки.

Каждый срез — отдельный коммит с зелёным полом. Капчур с UI идёт четвёртым: без него результат своих же срезов не увидеть.

## Тесты

- `ui_shell_*` — дерево игрового UI собирается в `World` без рендера; корни помечены `GameUiRoot`; активация кнопки инструмента меняет `UiState.tool` одним событием; значения HUD следуют `City`.
- `dev_ui_gated_*` — в дереве игрового UI по отдельности нет FPS, статуса MCP, поля сида, дампа и Load Test City; в сборке без `dev` `DevUiPlugin` не входит в `UiPlugin`.
- `notification_dedup_*` — однотипные уведомления схлопываются в одну строку со счётчиком, разные — нет, срок жизни группы считается от последнего.

## Проверка без окна

Верификатор поднимает скрытый экземпляр, снимает `simcity/capture {"ui": true}`, жмёт кнопки через `simcity/input {"activate": …}`, наводит `hover_tile`, переключает оверлей через `bevy_debugger/set_overlay`. Окно, курсор и клавиатура мака запрещены.

## Риски

- `bevy_ui_widgets` — молодой API. Если кнопка упрётся в его ограничения, она делается на `Interaction` и picking напрямую, без смены контракта `Activate` для проверок.
- Полнота первого офскрин-кадра с текстом (атлас глифов) и его масштаб не измерены — мерить на S4, прежде чем на кадры опираться.
- В dev-сборке egui-панели и игровой UI рисуются одновременно и могут перекрываться. Это касается только dev: в офскрин-кадр egui не попадает, в release его панелей нет.
