# План: починка зависаний машин на перекрёстках

## Контекст

Симптом: машины навсегда замирают на перекрёстках. Диагноз из анализа: сам пазфайндинг (A*, стоимости, кэш) здоров — заторы порождают ливлок стоп-линии, слепота stuck-детектора, бессмертные блокеры (автобусы/спецмашины), устаревшие lanelet-сайдкары после правки дорог и десинк светофоров. План — 6 независимых коммитов от малого к большому, чтобы минимизировать конфликты с сессией, которая сейчас занимается оптимизациями. Все правки в `crates/simcity_sim/`.

Ключевые ограничения кодовой базы (соблюдать везде): детерминизм — без RNG кроме `SimRng`/`jitter_seed`, новые системы встают в существующие `.chain()`-цепочки (pin `schedule_ambiguity_pin`), сортировка итераций где есть tiebreak.

## Commit 2 — ливлок стоп-линии (FIX A)

`crates/simcity_sim/src/game/traffic/movement/drive.rs:547-552`. Сейчас `max_p = (TILE_CENTER_TO_EDGE_TILES - STOP_LINE_OFFSET).max(0.0)` ≡ 0.0 (0.5 − 0.75), поэтому машина, удерживаемая boundary-клэмпом на 0.5 (`drive.rs:621-633`), при отказе `try_admit` телепортируется назад на 0.0 → вечный цикл 0→0.5→0, и каждый отскок «прогресс» (`|Δ| > 0.02`) обнуляет таймеры.

- В заблокированной ветке: `max_p = TILE_CENTER_TO_EDGE_TILES.max(prev_p)` — зеркально строгому полу из `drive.rs:626`. Отказ на границе оставляет машину стоять на 0.5, `at_boundary` остаётся true, `try_admit` ретраится каждый тик без дёрганья.
- Осознанный трейд-офф (в комментарии в коде): очередь на красный стоит «нос к боксу» на 0.5, а не на геометрической стоп-линии −0.25 — это уже контракт boundary-gated admission (`drive.rs:622-625`), менять его — крупная перестройка сериализации.
- Тесты: перезапустить `tests/traffic_lights.rs:139`, `tests/lanelet_arbiter.rs:1547/1825/1936` (по анализу совместимы). `tests/pedestrians.rs:10` пинирует верхнюю границу `−0.25+ε` — при провале ослабить до инварианта «не въехал в бокс»: `progress <= TILE_CENTER_TO_EDGE_TILES + 1e-6`.

## Commit 3 — слепота stuck-детектора к ожидающим (FIX B)

`crates/simcity_sim/src/game/traffic/stuck.rs:44-51, 171-177`. `WaitingForGreen`/`Stopped` обнуляют `stuck.secs` каждый тик безусловно, а резолвер таких пропускает — спасение целиком висит на motion-timer («wedged»), который для заблокированной машины рерутит в тот же маршрут.

- В `update_stuck_timers` добавить в запрос `Option<&VehicleMotionTimer>`; сброс таймера в ожидающих состояниях только пока `motion.stopped_secs < LIGHT_CYCLE_EXEMPT_SECS` (новая константа 45.0 рядом с кластером в `traffic.rs:144-157`; максимум цикла светофора ~42с с protected-left — 34с существует только в комментариях). После 45с ожидания таймер начинает копиться → на 60с честно срабатывает рерут.
- В `resolve_stuck_vehicles` удалить отдельный state-based skip (строки 171-177) — общий порог `stuck.secs < STUCK_REROUTE_SECS && !recovery_due` (строка 178) теперь корректно прикрывает и легитимные короткие ожидания (≤45с → secs ≈ 0 < 60 → пропуск).
- Сохранить свойство выживания nudge'а: `nudge_lanelet_stall_reroute` максимизирует `secs` после `update_stuck_timers` (порядок в цепочке уже верный, `traffic.rs:445-447`).
- Тесты: `stuck.rs:586` (`car_stopped_in_congestion_is_not_despawned` — выживание; сработает), `stuck.rs:468` (wedged-рерут). Добавить новый тест: `update_stuck_timers` + `WaitingForGreen` + `stopped_secs > 45` → `secs` растёт (сейчас поведение не запинировано никак).

## Commit 4 — устаревший lanelet-сайдкар (главный подозреваемый вечных заторов)

`VehicleLaneletPlan` (`traffic/components.rs:12-28`) хранит абсолютные `LaneletId` без версии графа; id перенумеровываются при каждом изменении дорог, арбитр доверяет сайдкару вслепую, промах `local_idx` молча выкидывает машину из кандидатов **каждый тик** (`arbiter.rs:849-857`) — она не попадает в `unresolved_this_tick`, stall-nudge (2с) на неё не действует; а совпавший по случайности id даёт чужую конфликт-строку (взаимная заморозка в боксе).

1. Версионирование: поле `built_for: u64` в `VehicleLaneletPlan`; проштамповать на всех местах записи — `spawn.rs:213/261` (из `p.lanelet_graph.built_for`), `reroute_planner.rs:107-115` (`into_spawn_parts` — версия параметром; все колл-сайты имеют `LaneletReplanRes` в скоупе) и `:213-226` (`apply_route`), `stuck.rs:246-248`, `swap_break.rs:282-284`, `lane_change/planning.rs:395-397`, `public_transport.rs:419`. Хелпер очистки сбрасывает в 0 (пустой план и так идёт в fallback).
2. Read-guard в арбитре (`arbiter.rs:843-846`): сайдкар заслуживает доверия только при `built_for == p.matrices.version` (версия уже вычислена на `:707`), иначе — геометрический fallback.
3. Rewire промаха (`arbiter.rs:849-857`): вместо `drop_other += 1; continue` — упасть в arm coarse как у None-arm (`drop_unresolved += 1`, `unresolved_this_tick.insert(e)`, `(true, 0usize, route_maneuver)`) — включает stall-tracker и 20-тиковый nudge. Для наблюдаемости добавить поле `drop_stale_sidecar` в `ArbiterTickStats` (`arbiter.rs:387-425`) и зеркалировать в `DebugArbiterLedgerState` (`simcity_debug/debug_world.rs:2230-2270`).
4. R3-sweep (`reroute_planner.rs:281-285`): для всё ещё легальных маршрутов со свежими тайлами, но устаревшим сайдкаром (`built_for != gv.0`, entries непусты) — очистить сайдкар (арбитр до следующего реплана живёт на fallback).
5. Тесты: новый регрессионный —写ать непустой сайдкар под версией N, bump `GraphVersion` (как `reroute_planner.rs:402`), прогнать арбитр → машина в `LaneletStallTracker.unresolved` и coarse, не в `drop_other`. Перепроверить `cache_local_idx_matches_row_order_and_rebuilds_on_version` (`arbiter.rs:2072`), `unresolved_turn_is_coarse_admitted_into_an_empty_box` (`lanelet_arbiter.rs:488`), счётчики в `arbiter_counts_one_straight_admit`.

## Commit 5 — бессмертные блокеры (FIX C; выбор пользователя — отмена миссии)

Автобусы и спецмашины исключены из всех despawn-веток (`stuck.rs:143-145, 155-157, 293-296`) — замороженная в боксе, она держит `inbox_mask` навсегда (комментарии в коде сами фиксируют «bus frozen 160s+ wedging whole arterials»).

1. Новый иммортал-хоризонт `IMMORTAL_RECOVER_SECS = 180.0` (тот же горизонт, что у обычных машин; триггер — не сбрасываемый `VehicleMotionTimer.stopped_secs`, не `stuck.secs`). Восстановление по решению пользователя:
   - `ServiceVehicle` в `EnRoute`/`OnScene` wedged ≥ 180с → форс-перевод в `Returning` + `apply_route` до станции (механика существующего mission-gone fallback, `services/systems.rs:223-234`, `emergencies/systems.rs:594-639`); миссия честно проваливается, юнит после возврата доступен для повторного выезда.
   - `Returning` wedged ≥ 180с → доесть маршрут (существующий трюк `stuck.rs:326-329` → `park_returned_service_vehicles` снапает на станцию).
   - `Bus` wedged ≥ 180с → форс варианта wedge-heal: `plan_from_tile` до следующей остановки со скипом текущего таргета (`public_transport.rs:614-631`), в обход `replan_cooldown_secs`.
   Реализовать расширением `recover_stuck_returning_service_vehicles` (→ `recover_stuck_service_vehicles`) + отдельным_BUS-вариантом в `tick_buses` или общей функцией в Recovery-цепочке (`traffic.rs:435-454`, добавить в `.chain()`); бюджет на тик по духу `MAX_UNSTUCK_PER_TICK` (например 2).
2. Починить невидимку: сборщик арбитра делает `continue` для машин с исчерпанным маршрутом (`arbiter.rs:763-766`) — запаркованная на тайле бокса машина не сеет `inbox_mask`, конфликтующие въезжают и клинятся за ней. Добавить сеяние inbox-строки (local_idx `None`) для in-box машин независимо от остатка маршрута.
3. Тесты: новый — EnRoute wedged (motion 181с) → state `Returning`, маршрут домой, `available_vehicles` восстановится после парк; новый — bus wedged → replan на следующую остановку; регресс `bus_with_exhausted_path_is_not_despawned` (`basic_behavior.rs:654`).

## Commit 6 — десинк светофорного сета и энтити (FIX E)

`arbiter.rs:135-141`: кластер в `traffic_lights`, но без живой `TrafficLight`-энтити → `ready: false` навсегда, при этом state-машина считает перекрёсток свободным потоком (`state.rs:179-188`) — машины подкатывают и замерают. Окно рассинхрона: немедленная мутация сета против deferred-спавна энтити (`lights.rs:185-245`), плюс вечный re-fire reconcile для id без кластера.

- В `lanelet_readiness` отсутствие энтити трактовать как **несигнализированный** перекрёсток (`ready: true`) — консистентно со state-машиной; починить и семантику RTOR (=false).
- Харденинг: в `detect_intersections` (`index.rs:153`) при ремапе удерживать в `traffic_lights` только id существующих кластеров (устраняет вечный re-fire reconcile).
- Счётчик `missing_light_treated_unsignalized` в `ArbiterTickStats` для наблюдаемости.
- Тест: сет содержит id без энтити → арбитр допускает по unsignalized-правилам, состояние FreeFlow.
